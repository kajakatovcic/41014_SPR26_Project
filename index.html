Overview

We took Track A: A TurtleBot3 Waffle Pi, simulated using MuJoCo, needs to cross a room with obstacles using its 2D LiDAR and then dock visually at a charging station marked with an ArUco tag. It has the platform's own sensors- wheel encoders (4096 ticks/rev), an LDS-01 LiDAR (360 beams, 0.12–3.5 m) and a 640×480 RGB camera.

We built the mission so it would carry over real hardware with no changes. The robot starts with no map, no route and no known start pose. All it knows is where the dock marker sits relative to a reference marker, which is measured when implemented on a real track. It localises from the reference marker, maps the room with its LiDAR as it drives, replans a smooth path around whatever it finds, and docks on the camera.

  • Model: A unicycle with a wheel actuator model derived from the MuJoCo parameters, plus the cross-track/heading error model the controller uses, with its controllability and observability analysed.
  • Estimator: An EKF on (x, y, θ) fusing encoder odometry with ArUco range and bearing. It is extended into EKF-SLAM for the explore mission with a LiDAR wall-line heading measurement.
  • Controller: LQR path following on a spline with curvature feed-forward, a Lyapunov turn on the spot, and Week 9 position-based visual servoing to dock. All of it runs on the estimate.

State and inputx = (x, y, θ), u = (v, ω); wheel radius 0.033 m, track 0.288 m

Control model2-state cross-track/heading error model, discretised by zero-order hold at T = 0.05 s
Estimator (C)
Predictionexact-arc unicycle on encoder odometry; Qd from a wheel error model (1% radius, 0.02 rad/√rad slip) × 3
UpdateArUco range and bearing, R from the perception noise model × (5, 1); χ² gate 11.83; lock-out recovery after 5 rejected frames
Explore extensionsinitial pose from PnP position and the LiDAR wall-line yaw; wall-line heading update (σ = 1°, gate 8.81); markers mapped by EKF-SLAM once the dock marker has been seen
Controller (D)
Planninglog-odds LiDAR occupancy grid (5 cm), A* with 0.30 m clearance, spline with curvature ≤ 15 /m
Path followingLQR, Bryson's rule (50 mm, 10°, 0.5 rad/s): Q = diag(400, 32.8), R = 4, gain-scheduled on speed; feed-forward ω = vκ; 0.15 m/s

Install and run

Python 3.12 on Windows (macOS and Linux work with the usual changes to the activate command).

git clone --recurse-submodules https://github.com/kajakatovcic/41014_SPR26_Project.git
cd 41014_SPR26_Project
python3.12 -m venv .venv
.venv\Scripts\activate
python -m pip install mujoco numpy matplotlib open3d spatialmath-python tqdm control sympy
python -m pip install opencv-contrib-python==4.10.0.84
python -m pip install --no-deps machinevision-toolbox-python
python -m pip install mvtb-data ansitable pgraph-python
python setup_tests/test_waffle_sensors.py        # check MuJoCo and the robot's sensors

Run the mission:

python main.py                          # explore mission: summary, LiDAR map, paths and estimation errors
python main.py --viewer                 # MuJoCo viewer in real time, plus the robot's camera in its own window
python main.py --obstacle-appears 20    # an obstacle appears in front of the robot at t = 20 s
python main.py --record                 # save the video (overview + camera) to videos/mission.mp4
python main.py --mission route          # the fixed-route baseline (known map and start pose)

Ground truth for evaluation ONLY

Following the assignment specs, the controller uses the estimated state and never ground truth. This is enforced in the structure of the loop and is visible in the code:

  • The controller is called with the estimate x_hat, the LiDAR points and the camera observations only: main.py lines 190–199.
  • The simulator's true pose is read only into the log which feeds the summary, the plots and the test scoring: main.py lines 209–216.
  • In the explore mission the estimator starts from its first marker sighting, not from the simulator. Before that, the estimate and the logs are empty.
  • The simulated wheel-radius errors and slip (SIM_WHEEL_SCALE_ERROR, SIM_WHEEL_SLIP_SIGMA) are never visible to the robot's software.
